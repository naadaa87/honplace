# 혼플 — 운영 안내

혼플은 ‘혼자 가기 좋은 플레이스’를 줄인 말입니다. 혼자 가도 어색하지 않은 곳을 모으고, 이름 없이 이야기를 남길 수 있는 서비스입니다.

- 저장소: https://github.com/naadaa87/honplace
- 사이트: https://honplace.com
- 관리자: https://honplace.com/admin

> `honplace.pages.dev` 로 들어오는 접속은 `honplace.com` 으로 자동 이동합니다.

---

## 1. 이 저장소의 구조

페이지는 **빌드로 생성**됩니다. `data/` 안의 JSON을 고치고 빌드를 돌리면 HTML이 다시 만들어집니다.

```
data/spaces.json       플레이스 데이터 (이것만 고치면 됩니다)
data/guides.json       '혼자 하는 법' 글
data/magazine.json     매거진 글
tools/build.mjs        생성기
tools/shell.mjs        공통 <head>·헤더·푸터 템플릿

index.html             홈
spaces.html            플레이스 전체 목록
place/<id>.html        플레이스 상세 (검색 노출의 핵심)
c/<분류>.html           분류별 모음
area/<지역>.html        동네별 모음
guide/index.html       혼자 하는 법 목차
guide/<id>.html        개별 안내 글
magazine/index.html    매거진 목차
magazine/<id>.html     개별 매거진 글
board.html             익명 게시판
admin.html             관리자
sitemap.xml / rss.xml / robots.txt / _redirects / _headers
functions/api/         Cloudflare Pages Functions (게시판·제보·호스트·관리 API)
schema.sql             D1 테이블 + 초기 글
```

## 2. 플레이스를 추가하거나 고치는 법

**방법 A — 관리자 화면 (추천)**

1. `/admin` 에 접속해 ADMIN_KEY 로 들어갑니다.
2. **플레이스** 탭의 편집기에서 내용을 고칩니다.
3. **검사**를 눌러 형식 오류가 없는지 확인합니다.
4. **파일 내려받기**로 `spaces.json` 을 받습니다.
5. 깃허브의 `data/spaces.json` 에 덮어쓰고 커밋합니다.
6. 아래 3번 빌드를 한 번 돌립니다.

**방법 B — 깃허브에서 직접**

`data/spaces.json` 을 열어 항목을 복사해 붙이고 내용을 바꿉니다.

| 항목 | 설명 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈만. 페이지 주소가 됩니다 (`/place/<id>`) |
| `kind` | `place`(실제 장소) 또는 `type`(타치노미처럼 형태를 소개하는 항목) |
| `cat` | honsul / honbap / cafe / culture / move / rest / learn / social |
| `area` | 시·구·동 수준. 동네별 페이지 분류에 쓰입니다 |
| `addr` | 전체 주소 (없으면 빈 문자열) |
| `solo` | 1~5. 혼자여도 눈에 안 띄는 정도 |
| `talk` | 0 조용히 / 1 원하면 한마디 / 2 이야기가 중심 |
| `price` | 표시용 문구 (예: "1~2만 원") |
| `tier` | 0 거의 무료 / 1 1~2만 원 / 2 3만 원 이상. 홈 예산 필터에 쓰입니다 |
| `time` | `day` `evening` `night` 중 해당하는 것들 |
| `tags` | 짧은 키워드 3~5개 |
| `intro` `culture` `first` | 어떤 곳인가 / 분위기와 문화 / 처음 가면 |
| `notes` | 주의사항 배열 |
| `mapq` | 지도 검색어. 보통 "이름 + 동네" |

## 3. 빌드 — 페이지를 다시 만들기

데이터를 고친 뒤에는 반드시 한 번 실행해야 새 페이지가 만들어집니다.

```bash
node tools/build.mjs
```

Node가 설치된 환경이면 어디서든 됩니다. 실행하면 `생성 완료 — N개 파일` 이 찍히고, 바뀐 HTML을 커밋하면 Cloudflare Pages가 1~2분 뒤 자동 배포합니다.

빌드는 **더 이상 데이터에 없는 페이지를 자동으로 지웁니다.** 폐업한 곳을 `spaces.json` 에서 빼고 빌드하면 그 페이지(`/place/<id>`)도 함께 사라집니다. 지워진 항목이 있으면 `정리 — 삭제된 페이지 N개` 가 먼저 찍힙니다. 정리 대상은 `place/` `c/` `area/` `guide/` `magazine/` 폴더의 HTML 뿐이고, 그 밖의 파일은 건드리지 않습니다.

> 빌드를 돌릴 수 없는 환경이라면, 데이터만 고쳐서 커밋해도 목록·필터·검색에는 반영됩니다. 다만 새 플레이스의 전용 페이지(`/place/<id>`)는 빌드를 해야 생기고, 지운 항목의 페이지도 빌드를 해야 없어집니다.

## 4. 데이터베이스(D1) — 게시판을 실제로 켜기

1. Cloudflare 대시보드 → **Workers & Pages** → **D1** → **Create database**. 이름은 `honplace-db`.
2. **Console** 탭에서 `schema.sql` 내용을 붙여 넣고 **Execute**.
3. Pages 프로젝트 → **Settings → Functions → D1 database bindings** → Variable name **DB**, 데이터베이스 `honplace-db`.
4. 같은 화면 **Environment variables** 에 추가:
   - `ADMIN_KEY` — 관리자 접속 키. 길게 만드세요.
   - `IP_SALT` — 선택. 도배 방지용 IP 해시에 섞는 값.
5. **Deployments** 탭에서 최신 배포 **Retry deployment**.

**확인**: `https://honplace.com/api/health` 에서 `{"ready":true}` 가 나오면 연결된 것입니다.

`/admin` 에 접속해 ADMIN_KEY 를 입력합니다. 키는 그 브라우저에만 저장됩니다.

| 글 관리 | 검색·필터·페이징, 숨기기·복구·삭제, 답글 확인과 삭제, 여러 건 일괄 처리 |

삭제는 되돌릴 수 없습니다. 애매하면 숨기기를 쓰세요.

## 6. 검색 노출(SEO) 설정

정식 주소는 **`https://honplace.com`** 입니다. 모든 canonical·og:url·sitemap·rss·구조화 데이터가 이 주소를 기준으로 생성됩니다.

**네이버 — 소유 확인 태그 반영 완료**

`tools/shell.mjs` 에 아래 태그가 들어가 있고, 빌드된 모든 페이지의 `<head>` 에 출력됩니다.

```html
<meta name="naver-site-verification" content="0efe77b67518e410ae0edd3bf246b4ef150bd949">
```

서치어드바이저에서 **소유확인** 버튼을 누르면 통과합니다.

> 서치어드바이저에 `http://honplace.com` 으로 등록되어 있다면, 확인이 끝난 뒤 `https://honplace.com` 도 따로 등록해 두세요. 네이버는 http 와 https 를 다른 사이트로 봅니다. 실제 서비스는 https 이므로 https 쪽에 사이트맵을 넣어야 수집이 제대로 됩니다.

**구글**

서치콘솔에 `honplace.com` 을 등록하고 받은 코드를 `tools/shell.mjs` 의 주석 처리된 `google-site-verification` 줄에 넣고 주석을 푼 뒤 빌드합니다.

**사이트맵 제출**

두 곳 모두 아래를 제출합니다. 네이버는 RSS도 함께 받습니다.

- `https://honplace.com/sitemap.xml` — 전체 페이지
- `https://honplace.com/rss.xml` — 매거진 (네이버)

### 주소를 또 바꾸게 되면

`tools/shell.mjs` 의 `SITE` 상수 한 줄만 고치고 `node tools/build.mjs` 를 실행하면 전 페이지에 반영됩니다. 단, **실제로 열리는 주소인지 먼저 확인**해야 합니다. 열리지 않는 주소로 바꾸면 모든 페이지의 canonical 이 없는 곳을 가리켜 검색에서 사라질 수 있습니다.

`pages.dev` 로 들어온 접속을 정식 주소로 보내는 규칙은 `_redirects` 에 들어 있고, 이 역시 `SITE` 값을 따라갑니다.

이미 적용되어 있는 것:

- 페이지마다 고유한 `<title>`, `description`, `canonical`
- 구조화 데이터 — Organization, WebSite, ItemList, LocalBusiness, Article, FAQPage, BreadcrumbList
- 빵부스러기 내비게이션과 촘촘한 내부 링크 (플레이스 ↔ 분류 ↔ 동네 ↔ 매거진)
- 목록을 빌드 시점에 HTML로 그려 두어 크롤러가 자바스크립트 없이 읽을 수 있음
- sitemap.xml 자동 생성, robots.txt (네이버 Yeti·구글·다음 명시), RSS

## 7. 호스트 등록

공간을 운영하는 분이 `/host` 에서 신청하면, 운영자가 확인한 뒤 인증 호스트가 됩니다.

### 흐름

1. **신청** — 호스트가 `/host` 에서 공간 정보, 담당자 연락처, 사업자등록번호, 혼자 오는 손님을 위한 안내를 보냅니다. 사업자등록번호는 국세청 체크섬으로 형식을 검증하고, 이미 접수·인증된 번호면 중복 접수를 막습니다.
2. **심사** — 관리자 화면의 **호스트** 탭에 쌓입니다. 지도와 국세청 사업자 조회 버튼으로 실재하는 공간인지 확인합니다.
3. **승인** — `인증 승인`을 누르면 상태가 `verified` 가 됩니다.
4. **반영** — 같은 카드의 `spaces.json 조각 복사`를 누르면 아래 형식이 복사됩니다. 플레이스 탭에서 해당 공간 항목 안에 붙여 넣고 빌드하면 공간 페이지에 호스트 안내가 나옵니다.

```json
"host": {
  "verified": "2026-10-27",
  "title": "운영자가 직접 쓴 안내",
  "seats": "카운터 10석",
  "hours": "평일 11:00~21:00",
  "note": "좌석이 카운터뿐이라 혼자 오시는 분이 대부분입니다.",
  "link": "https://instagram.com/..."
}
```

`host` 가 들어간 공간은 제목 옆에 **호스트 확인** 배지가 붙고, 본문에 호스트 안내 상자가 생기며, 하단의 호스트 등록 유도 문구가 사라집니다.

### 설계 원칙

혼플은 등급이나 순위를 매기지 않습니다. 호스트 등록은 **노출 순서에 영향을 주지 않으며**, 혼자 지수와 대화 온도는 등록 여부와 무관하게 같은 기준으로 적용합니다. 이 원칙은 `/host` 페이지와 이용약관 4조에 명시되어 있습니다. 호스트가 쓴 글은 익명 후기와 구분된 자리에 배지를 달고 표시되므로, 읽는 사람이 둘을 혼동하지 않습니다.

### 아직 만들지 않은 것

지금은 신청과 심사까지입니다. 호스트가 직접 로그인해 자기 공간 정보를 고치고 후기에 답글을 다는 기능은 다음 단계입니다. `hosts` 테이블에 `space_id` 와 `status` 를 두어 그 단계로 바로 이어지도록 설계해 두었습니다.

## 8. 오픈 전에 바꿔야 하는 것

사업자 정보는 이미 반영되어 있습니다. 바꾸려면 `tools/shell.mjs` 의 `BIZ` 상수 한 곳만 고치고 빌드하면 푸터·약관·개인정보처리방침에 모두 반영됩니다.

| 항목 | 현재 | 위치 |
|---|---|---|
| 운영사·대표·사업자번호·주소·문의 메일 | 반영 완료 | `tools/shell.mjs` 의 `BIZ` → 빌드 |
| 대표 전화번호 | 비워 둠 | `BIZ.phone` 에 값을 넣으면 푸터와 방침에 표시됩니다 |
| 약관·방침 시행일과 ‘초안’ 문구 | 미기입 | `tools/build.mjs` 의 terms·privacy → 빌드 |
| 통신판매업 신고번호 | 없음 | 호스트에게 요금을 받게 되면 신고 후 푸터에 추가해야 합니다 |

> 호스트 등록으로 개인정보(담당자 이름·연락처·사업자등록번호)를 수집하게 되었으므로, 개인정보처리방침을 전면 개정하고 수집 항목·목적·보유 기간·개인정보보호책임자를 명시했습니다. 실제 오픈 전에는 법률 검토를 한 번 받으시길 권합니다.

## 9. 브랜드 · 디자인

**이름** 혼플 = 혼자 + 플레이스. 풀어 쓰면 ‘혼자 가기 좋은 플레이스’.
**한 줄 문구** 오늘은 혼자 가기 좋은 플레이스로.

**모티프** 한 줄에 늘어선 플레이스, 그중 하나에 불이 켜져 있는 그림 하나로 통일했습니다.
- 로고: 바닥선 위에 불 켜진 곳 하나, 아직 불 안 켜진 곳 하나
- 홈 히어로: 같은 그림을 화면 폭으로 늘린 것. 불 켜진 자리는 요일마다 바뀝니다
- 혼자 지수: 같은 형태의 작은 불빛 다섯 개
- 페이지는 낮(흰 배경)에서 시작해 밤(어두운 푸터)으로 끝납니다

**색** 흰색 #FFFFFF, 연한 회색 #F3F3F0, 글자 #1C1C21. 포인트는 램프 노랑 #F3B640 하나, 글자용 꿀색 #9A6512.

**서체** 고운바탕(제목·문장·글) + 프리텐다드(메뉴·표·버튼). CDN에서 불러옵니다.

**구조 원칙**
- 홈의 추천은 버튼 나열이 아니라 사용자의 문장입니다. 시간 칸은 접속 시각으로 미리 채워집니다
- 게시글은 편지처럼 본문이 먼저, 끝에 "— 이름"으로 서명합니다
- 목록은 카드가 아니라 표와 목차입니다

## 10. 플레이스 정보에 대하여

등록된 곳은 언론 보도, 미쉐린 가이드, 공식 소개, 지역 매체 등 공개 자료를 바탕으로 정리한 것입니다. 운영시간·가격·입장 규칙은 자주 바뀌므로 각 페이지에 ‘방문 전 확인’ 문구를 두었습니다.

조사 과정에서 폐업·영업중단이 확인된 곳은 등록하지 않았습니다. 운영이 불확실한 곳은 `notes` 에 확인이 필요하다고 적어 두었습니다. 틀린 정보를 발견하면 각 페이지의 ‘정보 수정 제안’으로 접수되고, 관리자 **제보** 탭에서 확인할 수 있습니다.
