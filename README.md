# 혼플 — 운영 안내

혼플은 ‘혼자 가기 좋은 플레이스’를 줄인 말입니다. 혼자 가도 어색하지 않은 곳을 모으고, 이름 없이 이야기를 남길 수 있는 서비스입니다.

- 저장소: https://github.com/naadaa87/honplace
- 사이트: https://honplace.com
- 관리자: https://honplace.com/admin

> `honplace.pages.dev` 로 들어오는 접속은 `honplace.com` 으로 자동 이동합니다.

---

## 1. 이 저장소의 구조

페이지는 **빌드로 생성**됩니다. `data/` 안의 JSON을 고치고 빌드를 돌리면 HTML이 다시 만들어집니다.

```
data/spaces.json       플레이스 데이터 (이것만 고치면 됩니다)
data/photos.json       페이지에 미리 넣어 둘 지점 사진 (아래 2-1)
data/place-sources.json 지점 정보를 확인할 때 본 자료 주소 (사이트에는 표시하지 않음)
data/guides.json       '혼자 하는 법' 글
data/magazine.json     매거진 글
data/landing.json      분류·지역 페이지의 소개 글과 자주 묻는 것
data/test.json         혼자력 테스트 문항·결과 유형·채점표
data/prompts.json      게시판 '오늘의 질문' 목록
tools/build.mjs        생성기
tools/shell.mjs        공통 <head>·헤더·푸터 템플릿

index.html             홈
spaces.html            플레이스 전체 목록
place/<id>.html        플레이스 상세 (검색 노출의 핵심)
c/<분류>.html           분류별 모음
area/<지역>.html        동네별 모음
guide.html             혼자 하는 법 목차
guide/<id>.html        개별 안내 글
magazine.html          매거진 목차
magazine/<id>.html     개별 매거진 글
board.html             익명 게시판
test.html              혼자력 테스트
test/result/<유형>.html 테스트 결과 페이지 (5종)
host.html              호스트 등록 신청
host/center.html       호스트센터 (인증 호스트 전용, 검색 제외)

sitemap.xml / rss.xml / robots.txt / _redirects / _headers

schema.sql             D1 테이블 + 초기 글 (새로 만들 때)
migrations/            이미 있는 D1 에 열을 추가할 때 실행하는 SQL
```

## 2. 플레이스를 추가하거나 고치는 법

**방법 A — 관리자 화면 (추천)**

1. `/admin` 에 접속해 ADMIN_KEY 로 들어갑니다.
2. **플레이스** 탭의 편집기에서 내용을 고칩니다.
3. **검사**를 눌러 형식 오류가 없는지 확인합니다.
4. **파일 내려받기**로 `spaces.json` 을 받습니다.
5. 깃허브의 `data/spaces.json` 에 덮어쓰고 커밋합니다.
6. 아래 3번 빌드를 한 번 돌립니다.

**방법 B — 깃허브에서 직접**

`data/spaces.json` 을 열어 항목을 복사해 붙이고 내용을 바꿉니다.

| 항목 | 설명 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈만. 페이지 주소가 됩니다 (`/place/<id>`) |
| `kind` | `place`(실제 장소) 또는 `type`(타치노미처럼 형태를 소개하는 항목) |
| `cat` | honsul / honbap / cafe / culture / play / move / rest / learn / social |
| `area` | 시·구·동 수준. 동네별 페이지 분류에 쓰입니다 |
| `addr` | 전체 주소 (없으면 빈 문자열) |
| `solo` | 1~5. 혼자여도 눈에 안 띄는 정도 |
| `talk` | 0 조용히 / 1 원하면 한마디 / 2 이야기가 중심 |
| `price` | 표시용 문구 (예: "1~2만 원") |
| `tier` | 0 거의 무료 / 1 1~2만 원 / 2 3만 원 이상. 홈 예산 필터에 쓰입니다 |
| `time` | `day` `evening` `night` 중 해당하는 것들 |
| `tags` | 짧은 키워드 3~5개 |
| `intro` `culture` `first` | 어떤 곳인가 / 분위기와 문화 / 처음 가면 |
| `notes` | 주의사항 배열 |
| `mapq` | 지도 검색어. 보통 "이름 + 동네" |

아래는 **있으면 적는 항목**입니다. 적어 둔 것만 상세 페이지의 ‘한눈에 보기’와 ‘이용 정보’, ‘자주 묻는 것’에 나옵니다.

| 항목 | 설명 |
|---|---|
| `seats` | 자리 구성 (예: "카운터 10석", "창가 1인석") |
| `hours` | 운영 시간 (예: "화–일 10:00–19:00") |
| `closed` | 쉬는 날 |
| `transit` | 가는 길 (예: "2호선 시청역 10번 출구에서 걸어서 4분") |
| `menu` | 대표 메뉴와 가격, 또는 입장료 |
| `site` | 공식 누리집이나 인스타그램 주소 |
| `checked` | 정보를 마지막으로 확인한 달 (예: "2026-11"). 상세 페이지에 ‘2026년 11월에 확인한 정보’로 표시됩니다 |
| `verify` | `true` 로 두면 ‘최근 영업 여부를 다시 확인하고 있는 곳’이라는 안내가 붙습니다 |

`area` 는 "서울 종로구 청운동"처럼 **시·도로 시작**하게 적습니다. 동네별 페이지는 이 값으로 묶이고(`tools/build.mjs` 의 `AREA_DEFS`), 마지막 낱말이 페이지 제목의 괄호 안에 들어갑니다.

## 2-1. 사진

지점 사진은 두 군데에서 옵니다. 둘 다 있으면 올린 사진이 앞에 놓입니다.

| 어디에 | 누가 | 언제 보이나 |
|---|---|---|
| D1 의 `photos` 테이블 | 관리자 **사진** 탭, 호스트센터 **사진** 탭 | 올린 뒤 바로 (상세 페이지는 1분, 목록 카드는 10분 안에 반영) |
| `data/photos.json` | 깃허브에서 직접 | 빌드 후. 검색엔진과 공유 미리보기(og:image)에도 쓰입니다 |

**쓸 수 있는 사진은 세 가지뿐입니다.** 직접 찍은 사진, 그 공간의 운영자에게 받은 사진, 누구나 쓸 수 있게 공개된 사진(위키미디어 공용, 공공누리 등). 네이버 지도·블로그·인스타그램에 올라온 사진은 주인이 따로 있어 그대로 가져다 쓸 수 없습니다. 그래서 상세 페이지에는 사진 아래 ‘네이버지도에서 사진 보기’ 링크를 따로 두었습니다.

관리자 **사진** 탭에서 지점을 고르면 세 가지 방법으로 넣을 수 있습니다.

1. **사진 파일 올리기** — 휴대폰이나 컴퓨터의 사진을 고르면 브라우저가 긴 변 1600px 로 줄여서 올립니다. 한 지점에 30장까지.
2. **위키미디어 공용에서 찾기** — 궁·미술관·공원·도서관 같은 공공장소에 잘 맞습니다. 검색 결과에서 고르면 작성자·라이선스·원본 주소가 함께 등록되고 상세 페이지에 출처로 표시됩니다. 라이선스 정보가 없는 사진은 등록되지 않습니다.
3. **사진 주소로 등록** — 공공누리처럼 다른 곳의 자유 이용 사진. 출처와 라이선스를 직접 적습니다.

사진이 없는 지점은 그 지점의 태그와 혼자 지수를 그린 표지가 대신 나옵니다.

`data/photos.json` 형식 (관리자 사진 탭의 **photos.json 조각 복사**로 만들 수 있습니다):

```json
{ "photos": { "deoksugung": [
  { "src": "https://…/960px.jpg", "thumb": "https://…/500px.jpg", "alt": "대한문",
    "credit": "작성자 / 위키미디어 공용", "license": "CC BY-SA 4.0", "source": "https://commons.wikimedia.org/wiki/File:…" }
] } }
```

올린 사진은 D1 에 글자(base64)로 들어갑니다. 한 장이 300KB 안팎이라 무료 D1(데이터베이스당 500MB)로 천 장 넘게 담을 수 있습니다. 그보다 많아지면 Cloudflare R2 로 옮기는 것이 맞습니다.

## 3. 빌드 — 페이지를 다시 만들기

데이터를 고친 뒤에는 반드시 한 번 실행해야 새 페이지가 만들어집니다.

```bash
node tools/build.mjs
```

Node가 설치된 환경이면 어디서든 됩니다. 실행하면 `생성 완료 — N개 파일` 이 찍히고, 바뀐 HTML을 커밋하면 Cloudflare Pages가 1~2분 뒤 자동 배포합니다.

빌드는 **더 이상 데이터에 없는 페이지를 자동으로 지웁니다.** 폐업한 곳을 `spaces.json` 에서 빼고 빌드하면 그 페이지(`/place/<id>`)도 함께 사라집니다. 지워진 항목이 있으면 `정리 — 삭제된 페이지 N개` 가 먼저 찍힙니다. 정리 대상은 `place/` `c/` `area/` `guide/` `magazine/` 폴더의 HTML 뿐이고, 그 밖의 파일은 건드리지 않습니다.

> 빌드를 돌릴 수 없는 환경이라면, 데이터만 고쳐서 커밋해도 목록·필터·검색에는 반영됩니다. 다만 새 플레이스의 전용 페이지(`/place/<id>`)는 빌드를 해야 생기고, 지운 항목의 페이지도 빌드를 해야 없어집니다.

## 4. 데이터베이스(D1) — 게시판을 실제로 켜기

1. Cloudflare 대시보드 → **Workers & Pages** → **D1** → **Create database**. 이름은 `honplace-db`.
2. **Console** 탭에서 `schema.sql` 내용을 붙여 넣고 **Execute**.
3. Pages 프로젝트 → **Settings → Functions → D1 database bindings** → Variable name **DB**, 데이터베이스 `honplace-db`.
4. 같은 화면 **Environment variables** 에 추가:
   - `ADMIN_KEY` — 관리자 접속 키. 길게 만드세요.
   - `IP_SALT` — 선택. 도배 방지용 IP 해시에 섞는 값.
5. **Deployments** 탭에서 최신 배포 **Retry deployment**.

**확인**: `https://honplace.com/api/health` 에서 `{"ready":true}` 가 나오면 연결된 것입니다.

### 이미 D1 을 만들어 둔 경우 — 마이그레이션

`schema.sql` 은 새 데이터베이스용입니다. **이미 테이블이 있는 D1** 에는 `migrations/` 안의 파일을 번호 순서대로 Console 에 붙여 넣어 실행하세요.

| 파일 | 하는 일 |
|---|---|
| `migrations/002-host-center.sql` | `comments.is_host`, `hosts.host_key`, `hosts.pub_*` 열 추가 (호스트센터) |
| `migrations/003-analytics.sql` | `pv`(페이지 조회)·`ev`(클릭·행동)·`likes`(가고 싶어요) 테이블 추가 (관리자 KPI) |
| `migrations/004-photos.sql` | `photos`(지점 사진) 테이블 추가 (관리자·호스트센터 사진 탭) |

이미 적용된 줄은 `duplicate column name` 오류가 나는데, 그 줄만 건너뛰면 됩니다. 관리자 화면 호스트 탭 상단에 ‘열이 아직 없습니다’ 안내가 보이면 002가, KPI 탭 상단에 ‘방문 통계 테이블이 아직 없습니다’가 보이면 003이 필요한 상태입니다. 003은 모두 `IF NOT EXISTS`라 두 번 실행해도 됩니다.

## 5-1. KPI — 방문·클릭·인기 지점

관리자 화면 **KPI** 탭. 외부 분석 도구 없이 혼플이 직접 모읍니다. `migrations/003-analytics.sql` 을 실행한 뒤부터 쌓입니다.

### 어떻게 모으나

모든 페이지의 `common.js` 가 페이지를 열 때 `/api/t` 로 아주 작은 기록을 보냅니다.

| 기록 | 내용 |
|---|---|
| 페이지 조회 (`pv`) | 경로, 페이지 유형, 플레이스 id, 들어온 경로(네이버·구글 검색 / SNS / 외부 링크 / 캠페인 / 직접), 기기, 첫 방문 여부, 방문의 첫 페이지 여부 |
| 체류시간 | 화면이 실제로 보이던 시간만. 다른 탭에 가 있던 시간은 빼고 30분이 넘으면 30분으로 자름 |
| 클릭·행동 (`ev`) | 지도 버튼(네이버·구글·카카오), 외부 링크, 메일, 공유, 가고 싶어요, 목록 검색어·필터, 테스트 시작·결과, 글쓰기, 호스트 신청, 제보, 주요 버튼(`data-track`) |
| 가고 싶어요 (`likes`) | 플레이스 페이지의 저장 버튼. 브라우저당 한 번, 이 기기의 ‘저장한 곳’ 목록(`/spaces?saved=1`)에도 남음 |

방문자는 브라우저에 저장한 무작위 번호로만 구분합니다. 이름·연락처·IP 원문은 저장하지 않고 쿠키도 쓰지 않습니다. 검색엔진 봇, `/admin`, 브라우저의 ‘추적 안 함(DNT)’·GPC 설정, KPI 탭의 **‘이 브라우저의 내 방문은 빼기’** 를 켠 브라우저는 기록하지 않습니다. 400일이 지난 기록은 자동으로 지웁니다. 이 내용은 개인정보처리방침 3-1에 반영했습니다.

### 화면 구성

1. **기간** — 오늘 / 7일 / 30일 / 90일 / 직접 지정. 모든 숫자는 길이가 같은 직전 기간과 비교합니다(▲▼, 이탈률은 줄어야 초록). 비교 기간이 수집 시작 전이면 그렇다고 표시합니다.
2. **핵심 지표** — 방문자(신규·재방문), 페이지뷰, 방문 수, 평균 체류시간, 이탈률, 지도 열기, **지도 전환율**(플레이스를 본 방문 중 지도를 연 비율 — 실제로 가 보려는 사람에 가장 가까운 지표), 가고 싶어요. 지금 접속 중(최근 5분)도 위에 보입니다.
3. **일별 추이** — 방문자·페이지뷰·방문 수·지도 열기·가고 싶어요·새 글 중 골라서. ‘오늘’이면 시간대별로 보입니다.
4. **시간대별·요일별 방문**, **어디서 들어왔나**(네이버·구글·SNS 등), **기기**, **페이지 유형**
5. **인기 지점** — 조회수·방문자·지도 열기·지도 전환율·가고 싶어요·후기·체류시간으로 정렬. 네이버/구글 지도 비율, 기간/누적 좋아요·후기. 이 기간에 한 번도 열리지 않은 지점 목록. CSV 내려받기.
6. **페이지별 방문** — 유형별로 걸러 보기, 평균 체류, 첫 페이지로 들어온 수, 이탈률. CSV.
7. **검색으로 들어온 페이지** — 네이버·구글에서 어떤 글과 장소가 잘 걸리는지. **유입 상세**와 검색어·캠페인.
8. **클릭과 행동**, **혼자력 테스트**(시작→완료, 결과 분포), **목록에서 찾은 말**, **많이 쓴 필터**
9. **커뮤니티** — 새 글, 플레이스 후기, 답글, 받은 반응, 신고, 제보, 글쓴이 수
10. **회원(호스트)** — 혼플은 익명 원칙이라 일반 회원가입이 없습니다. 계정(호스트 키)을 가진 회원은 호스트뿐이라 전체·인증·기간 내 가입·심사 대기와 회원 목록(담당자·이메일·상태·가입일·인증일·안내 수정일·답글 수)을 보여 줍니다. CSV.

탭 맨 아래 ‘지표는 이렇게 셉니다’에 정의를 적어 두었습니다.

## 6. 검색 노출(SEO) 설정

정식 주소는 **`https://honplace.com`** 입니다. 모든 canonical·og:url·sitemap·rss·구조화 데이터가 이 주소를 기준으로 생성됩니다.

**네이버 — 소유 확인 태그 반영 완료**

`tools/shell.mjs` 에 아래 태그가 들어가 있고, 빌드된 모든 페이지의 `<head>` 에 출력됩니다.

```html
<meta name="naver-site-verification" content="0efe77b67518e410ae0edd3bf246b4ef150bd949">
```

서치어드바이저에서 **소유확인** 버튼을 누르면 통과합니다.

> 서치어드바이저에 `http://honplace.com` 으로 등록되어 있다면, 확인이 끝난 뒤 `https://honplace.com` 도 따로 등록해 두세요. 네이버는 http 와 https 를 다른 사이트로 봅니다. 실제 서비스는 https 이므로 https 쪽에 사이트맵을 넣어야 수집이 제대로 됩니다.

**구글**

서치콘솔에 `honplace.com` 을 등록하고 받은 코드를 `tools/shell.mjs` 의 주석 처리된 `google-site-verification` 줄에 넣고 주석을 푼 뒤 빌드합니다.

**사이트맵 제출**

두 곳 모두 아래를 제출합니다. 네이버는 RSS도 함께 받습니다.

- `https://honplace.com/sitemap.xml` — 전체 페이지
- `https://honplace.com/rss.xml` — 매거진 (네이버)

### 주소를 또 바꾸게 되면

`tools/shell.mjs` 의 `SITE` 상수 한 줄만 고치고 `node tools/build.mjs` 를 실행하면 전 페이지에 반영됩니다. 단, **실제로 열리는 주소인지 먼저 확인**해야 합니다. 열리지 않는 주소로 바꾸면 모든 페이지의 canonical 이 없는 곳을 가리켜 검색에서 사라질 수 있습니다.

`pages.dev` 로 들어온 접속을 정식 주소로 보내는 규칙은 `_redirects` 에 들어 있고, 이 역시 `SITE` 값을 따라갑니다.

이미 적용되어 있는 것:

- 페이지마다 고유한 `<title>`, `description`, `canonical`
- 구조화 데이터 — Organization, WebSite, ItemList, LocalBusiness, Article, FAQPage, BreadcrumbList
- 빵부스러기 내비게이션과 촘촘한 내부 링크 (플레이스 ↔ 분류 ↔ 동네 ↔ 매거진)
- 목록을 빌드 시점에 HTML로 그려 두어 크롤러가 자바스크립트 없이 읽을 수 있음
- sitemap.xml 자동 생성, robots.txt (네이버 Yeti·구글·다음 명시), RSS

## 7. 호스트 등록과 호스트센터

공간을 운영하는 분이 `/host` 에서 신청하면 운영자가 확인한 뒤 인증 호스트가 되고, 그때부터 `/host/center` 에서 직접 안내를 고치고 후기에 답할 수 있습니다.

### 흐름

1. **신청** — `/host` 에서 공간 정보, 담당자 연락처, 사업자등록번호, 혼자 오는 손님을 위한 안내를 보냅니다. 사업자등록번호는 국세청 체크섬으로 형식을 검증하고, 이미 접수·인증된 번호면 중복 접수를 막습니다.
2. **심사** — 관리자 화면 **호스트** 탭에 쌓입니다. 지도와 국세청 사업자 조회 버튼으로 실재하는 공간인지 확인합니다.
3. **승인** — `인증 승인`을 누르면 상태가 `verified` 가 되고 **호스트 키**(`hk-` 로 시작하는 14자)가 만들어집니다. 신청 때 적은 안내가 공개 안내의 초안으로 옮겨집니다.
4. **키 전달** — 카드의 `키 복사` 또는 `안내 메일 열기`를 눌러 신청자 이메일로 키를 보냅니다. 자동 발송은 없습니다(메일 서버가 없으므로 운영자의 메일 앱이 열립니다).
5. **호스트센터** — 호스트가 `/host/center` 에 키를 넣고 들어옵니다. 키는 그 브라우저에만 저장되고 서버에는 `Authorization: Bearer` 헤더로만 보냅니다.

### 호스트센터에서 할 수 있는 것

| 탭 | 내용 |
|---|---|
| 호스트 안내 | 제목·1인 좌석·운영 시간·본문·공식 채널 링크를 고치고 저장. 저장 즉시 공간 페이지의 호스트 안내 상자에 반영(최대 1분 캐시). 미리 보기 제공 |
| 후기와 답글 | 내 공간에 달린 글 목록. 글마다 호스트 답글 하나, 지우고 다시 쓸 수 있음. 답글에는 ‘인증 호스트’ 표시가 붙음 |
| 사진 | 내 공간 사진을 8장까지 올리고 대표 사진을 고름. 올린 사진은 공간 페이지와 목록 카드에 ‘○○ 제공’으로 표시. 운영자가 숨길 수 있음 |
| 잘 쓰는 법 | 답글 원칙, 안내를 고칠 때, 자주 묻는 것(키 분실·정보 수정·탈퇴) |

상단에는 남겨진 후기 수, 받은 반응, 내가 단 답글 수, 안내 게시 여부가 보입니다.

### 안내 글의 규칙

- 본문 20자 이상, 1200자까지. 연락처·링크는 본문과 답글에 넣을 수 없고 ‘공식 채널’ 칸에만 넣습니다.
- ‘최고’ ‘강추’ ‘무조건’ 같은 홍보 표현이 둘 이상이면 저장을 거부합니다. 광고가 아니라 안내여야 한다는 원칙을 코드로 둔 것입니다.
- 가게 이름·주소·분류·혼자 지수·대화 온도는 호스트가 바꿀 수 없습니다(검색엔진에 고정으로 실리는 부분). 문의 메일로 받아 운영자가 고칩니다.

### 공간 페이지에 보이는 방식

빌드 때 `spaces.json` 의 `host` 항목이 있으면 그 내용이 정적으로 들어가고(검색엔진용 고정본), 페이지가 열리면 `place.js` 가 `/api/space/<id>/host` 를 불러 D1 의 최신 안내로 바꿔 끼웁니다. 그러니 **호스트가 저장한 내용은 빌드 없이 바로 보이고**, 검색엔진용 고정본까지 바꾸려면 관리자 카드의 `spaces.json 조각 복사`로 데이터에도 넣어 주면 됩니다.

```json
"host": {
  "verified": "2026-10-27",
  "title": "운영자가 직접 쓴 안내",
  "seats": "카운터 10석",
  "hours": "평일 11:00~21:00",
  "note": "좌석이 카운터뿐이라 혼자 오시는 분이 대부분입니다.",
  "link": "https://instagram.com/..."
}
```

### API

| 경로 | 인증 | 하는 일 |
|---|---|---|
| `POST /api/host` | 없음 | 호스트 등록 신청 |
| `GET /api/host/me` | 호스트 키 | 내 정보·공개 안내·통계 |
| `POST /api/host/content` | 호스트 키 | 공개 안내 저장 |
| `GET/POST/DELETE /api/host/reviews` | 호스트 키 | 내 공간의 글 목록 / 답글 달기 / 내 답글 지우기 |
| `GET/POST/DELETE /api/host/photos` | 호스트 키 | 내 공간 사진 목록 / 올리기·대표 지정 / 지우기 |
| `GET /api/space/<id>/host` | 없음 | 공간 페이지가 읽는 공개 안내 (연락처·사업자번호는 절대 내보내지 않음) |
| `GET /api/space/<id>/photos` | 없음 | 공간 페이지가 읽는 올린 사진 목록 |
| `GET /api/photos/covers` | 없음 | 목록 카드가 읽는 지점별 대표 사진 |
| `GET /api/photo/<id>` | 없음 | 올린 사진 파일 (`?s=t` 는 작은 사진) |
| `POST /api/admin` `action:"host-rekey"` | 관리자 키 | 키 재발급 (이전 키 즉시 무효) |

### 설계 원칙

혼플은 등급이나 순위를 매기지 않습니다. 호스트 등록은 **노출 순서에 영향을 주지 않으며**, 혼자 지수와 대화 온도는 등록 여부와 무관하게 같은 기준으로 적용합니다. 이 원칙은 `/host` 페이지와 이용약관 4조에 명시되어 있습니다. 호스트가 쓴 글은 익명 후기와 구분된 자리에 배지를 달고 표시되므로 읽는 사람이 둘을 혼동하지 않습니다.

로그인 대신 키를 쓰는 이유는 비밀번호 재설정 메일, 세션 관리 같은 기반 없이도 안전하게 운영하기 위해서입니다. 키는 D1 에 평문으로 있으니 D1 접근 권한 자체를 관리자에게만 두세요. 키가 새면 관리자 화면에서 재발급하면 됩니다.

### 아직 만들지 않은 것

호스트가 여러 공간을 하나의 키로 관리하는 것, 호스트에게 새 후기 알림을 보내는 것, 호스트 쪽 통계 기간 선택. 필요해지면 `hosts` 테이블에 열을 더하는 수준으로 이어집니다.

## 8. 오픈 전에 바꿔야 하는 것

사업자 정보는 이미 반영되어 있습니다. 바꾸려면 `tools/shell.mjs` 의 `BIZ` 상수 한 곳만 고치고 빌드하면 푸터·약관·개인정보처리방침에 모두 반영됩니다.

| 항목 | 현재 | 위치 |
|---|---|---|
| 운영사·대표·사업자번호·주소·문의 메일 | 반영 완료 | `tools/shell.mjs` 의 `BIZ` → 빌드 |
| 대표 전화번호 | 비워 둠 | `BIZ.phone` 에 값을 넣으면 푸터와 방침에 표시됩니다 |

## 8-1. 커뮤니티 요소와 혼자력 테스트

| 혼자 놀기 분류 | `/c/play` | 코인 노래방·오락실·배팅장·볼링 등 10개 유형과 24시간 만화카페 2곳 |

테스트 결과 페이지의 추천 플레이스는 `test.json` 각 유형의 `filter`(혼자 지수·대화 온도·비용)와 `cats`(선호 분류)로 빌드 때 고릅니다.

## 9. 브랜드 · 디자인

**이름** 혼플 = 혼자 + 플레이스. 풀어 쓰면 ‘혼자 가기 좋은 플레이스’.
**한 줄 문구** 오늘은 혼자 가기 좋은 플레이스로.

**모티프** 한 줄에 늘어선 플레이스, 그중 하나에 불이 켜져 있는 그림 하나로 통일했습니다.
- 로고: 바닥선 위에 불 켜진 곳 하나, 아직 불 안 켜진 곳 하나
- 홈 히어로: 같은 그림을 화면 폭으로 늘린 것. 불 켜진 자리는 요일마다 바뀝니다
- 혼자 지수: 같은 형태의 작은 불빛 다섯 개
- 페이지는 낮(흰 배경)에서 시작해 밤(어두운 푸터)으로 끝납니다

**색** 흰색 #FFFFFF, 연한 회색 #F3F3F0, 글자 #1C1C21. 포인트는 램프 노랑 #F3B640 하나, 글자용 꿀색 #9A6512.

**서체** 고운바탕(제목·문장·글) + 프리텐다드(메뉴·표·버튼). CDN에서 불러옵니다.

**구조 원칙**
- 홈의 추천은 버튼 나열이 아니라 사용자의 문장입니다. 시간 칸은 접속 시각으로 미리 채워집니다
- 게시글은 편지처럼 본문이 먼저, 끝에 "— 이름"으로 서명합니다
- 목록은 카드가 아니라 표와 목차입니다

## 10. 플레이스 정보에 대하여

등록된 곳은 언론 보도, 미쉐린 가이드, 공식 소개, 지역 매체 등 공개 자료를 바탕으로 정리한 것입니다. 운영시간·가격·입장 규칙은 자주 바뀌므로 각 페이지에 ‘방문 전 확인’ 문구를 두었습니다.

각 지점을 확인할 때 본 자료의 주소는 `data/place-sources.json` 에 모아 두었습니다. 정보를 다시 확인할 때 여기서 시작하면 됩니다. 2026년 11월에 다시 확인한 곳은 `checked` 에 날짜가 있고, 날짜가 없는 곳은 아직 다시 확인하지 못한 곳입니다.

조사 과정에서 폐업·영업중단이 확인된 곳은 등록하지 않았습니다. 운영이 불확실한 곳은 `notes` 에 확인이 필요하다고 적어 두었습니다. 틀린 정보를 발견하면 각 페이지의 ‘정보 수정 제안’으로 접수되고, 관리자 **제보** 탭에서 확인할 수 있습니다.
